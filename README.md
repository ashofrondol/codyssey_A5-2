## 프로젝트 개요

이 미션은 금융 고객 데이터(`finance_data.csv`)로 **"AI가 왜 이런 판정을 했는가?"** 를 사람에게 설명하는 분석 파이프라인을 만든다. 먼저 정답(라벨) 없이 비슷한 고객끼리 묶는 **군집화(Clustering)** 로 고객 페르소나(persona, 대표 고객 유형)를 찾는다. 다음으로 분류 모델이 대출 승인/거절(연체 위험)을 예측하고, **SHAP**(각 변수가 예측을 얼마나 올리고 내렸는지 숫자로 나눠 보여 주는 설명 방법)으로 그 판정의 근거를 그림으로 설명한다. 금융 규제 당국이 대출 거절 사유 설명을 요구하는 것처럼, 블랙박스 모델의 판단을 투명하게 만드는 것이 목적이다. 마지막으로 분석 결과를 비기술자도 읽을 수 있는 비즈니스 인사이트 리포트(README.md)로 정리한다.

**핵심 과제** (명세의 핵심 스토리라인)

1. 군집화로 고객 페르소나(누구인가)를 도출한다.
2. 분류 모델로 거절/승인을 예측한다.
3. SHAP으로 "왜 그런 판정인가"를 설명한다. 군집별 대표 고객을 골라 Local SHAP으로 그 페르소나의 예측 근거까지 연결한다.

명세는 같은 질문이 Mobility("왜 이 경로/판단을 했는가?"), Energy, Healthcare, E-Commerce 등 다른 도메인에도 그대로 적용된다고 안내한다.

## 학습 목표

과제를 마치면 아래를 스스로 설명할 수 있어야 한다. (명세 "과제 목표")

- 정답이 없는 데이터에서 거리(Distance) 기반으로 군집을 형성하는 원리
- Elbow Method와 Silhouette Score를 활용하여 최적의 K(군집 수)를 결정하는 방법
- 차원 축소(PCA)의 의미와 Explained Variance(설명된 분산)의 해석
- SHAP 값을 활용해 복잡한 모델의 예측 결과를 변수별 기여도로 설명하는 방법
- Global Interpretation(Summary Plot: 전체 변수 영향)과 Local Interpretation(Force Plot: 개별 예측 이유)의 차이
- 기술적 분석 결과를 비기술자(예: 영업팀)에게 비즈니스 언어로 전달하는 방법
- PCA의 주성분(PC)이 원본 특성(Feature)과 다르다는 점, 그리고 해석할 때 둘을 혼동하지 않는 방법

### 데이터를 다룰 때 주의할 점

- **A5-1과 같은 파일인지 확인한다.** 두 레포의 `finance_data.csv`가 같아야 "Mission 23의 데이터를 그대로 사용"한 것이 된다. 행 수 10,000과 연체 비율 12.01%가 같은지 보면 된다.
- **`.gitignore`에 `*.csv`를 넣는다.** 지금 `.gitignore`에는 `*.csv`가 없다. A5-1 명세가 데이터 파일을 저장소에 올리지 말라고 했으므로 여기서도 같은 규칙을 따른다.
- **컬럼을 더하지 않는다.** "소득 대비 소비" 같은 파생 변수도 "임의 컬럼 추가"에 해당할 수 있다. 페르소나를 설명할 때는 원래 6개 변수의 평균과 분포만으로 말한다.
- **군집이 뚜렷하게 나뉘지 않는다.** 입력 변수 6개가 서로 상관없이 고르게 퍼져 있어서, 원래 "뭉쳐 있는 고객 무리"가 없다. 그래서 Silhouette Score가 0.13 안팎으로 낮고 PCA 2개 축이 약 35%만 설명한다. 명세 결과 예시(Silhouette 0.42, PC1 + PC2 = 73%)와 크게 다른 숫자가 나와도 계산이 틀린 것이 아니다. 리포트의 "한계" 칸에 이 이유를 적고, K는 명세 가이드대로 페르소나의 해석 가능성을 함께 보고 정한다.
- **`credit_score` → `is_overdue` 누수.** `is_overdue`는 `credit_score`가 하위 15%인지로 정해진다. 분류 모델 입력에 `credit_score`를 넣으면 SHAP Summary Plot에서 `credit_score` 하나가 거의 모든 설명을 차지한다. [명세에서 확인할 점](#명세에서-확인할-점) 참고.
- **타겟과 상관없는 변수가 있다.** 생성 코드에서 `age`, `spending_score`, `credit_card_count`는 어느 타겟 계산에도 쓰이지 않는다. 이 변수들의 SHAP 값은 0 근처로 나오는 것이 정상이며, 페르소나 설명에는 쓸 수 있어도 "거절 사유"로 해석하면 안 된다.

## 할 일

명세의 기능 요구 사항이다. 끝낸 항목은 `[x]`로 바꾼다.

### 1. 데이터 준비

이전 미션(Mission 23)과 같은 데이터를 쓰고, 군집화에는 "답"에 해당하는 타겟 변수를 빼고 고객 정보만 넣는다.

- [ ] Mission 23에서 생성한 `finance_data.csv` 파일을 그대로 사용한다.
- [ ] 군집화 분석 시에는 타겟 변수(신용 점수 `credit_score`, 연체 여부 `is_overdue`)를 제외하고 입력 변수(Feature)만 사용한다.
- [ ] 전처리는 허용 범위(원본 CSV 기준 스케일링, 결측치 처리, 이상치 제거 등)에서만 하고, 임의 컬럼 추가, 외부 데이터 병합, 데이터 증강은 하지 않는다.

### 2. 고객 군집화 (Clustering)

K-Means는 거리가 가까운 고객끼리 K개 묶음으로 나누는 방법이다. 변수마다 단위(나이, 만원 등)가 달라서 먼저 스케일링(값의 범위를 비슷하게 맞추기)을 한다. PCA는 여러 변수를 정보가 가장 많이 남는 2개 축으로 줄여 평면 그림으로 볼 수 있게 한다.

- [ ] K-Means 적용 전에 데이터 스케일링을 수행한다.
- [ ] Elbow Method와 Silhouette Score를 통해 최적의 군집 수(K)를 선정한다.
- [ ] K 결정 가이드를 따른다: Silhouette Score를 우선 기준, Elbow를 보조 기준으로 하고, 최종적으로 페르소나의 해석 가능성(명확성)을 고려해 선정한다.
- [ ] PCA를 적용하여 군집 결과를 2차원 산점도로 시각화한다(군집별 색상 구분).
- [ ] PCA 시각화에 Explained Variance Ratio(설명된 분산 비율)를 표시한다.
- [ ] 각 군집의 통계적 특징과 페르소나를 정의한다.

### 3. 모델 해석 (XAI)

XAI(설명 가능한 AI)는 모델의 판단 이유를 보여 주는 기술이다. Summary Plot은 모델 전체에서 어떤 변수가 중요한지(Global), Force/Waterfall Plot은 고객 한 명의 판정 이유(Local), Dependence Plot은 한 변수의 값이 바뀔 때 예측이 어떻게 변하는지를 보여 준다.

- [ ] Tree 기반 모델(Random Forest 등)에 shap 라이브러리를 적용한다.
- [ ] TreeExplainer를 우선 사용하고, KernelExplainer는 지양한다.
- [ ] Summary Plot으로 전체 변수 중요도와 방향성을 시각화하고 PNG로 저장한다. (Global Interpretation)
- [ ] 승인 케이스 1건, 거절 케이스 1건을 선정 기준에 따라 고른다(군집별 대표 고객과 연결 권장).
- [ ] Force Plot 또는 Waterfall Plot으로 개별 데이터(승인/거절 케이스)의 예측 원인을 시각화하고 저장한다(Waterfall PNG 권장 또는 Force Plot HTML 캡처/저장). (Local Interpretation)
- [ ] Dependence Plot으로 특정 변수 변화에 따른 예측값 추이를 시각화하고 PNG로 저장한다(특정 변수 1개 이상).
- [ ] Dependence Plot 변수 선택 기준을 따른다: Summary Plot 상위 변수 1~2개 + 비즈니스 의미가 큰 변수 1개.
- [ ] Dependence Plot에 대한 인사이트를 2문장 이상 쓴다.

### 4. 인사이트 리포트

그래프를 처음 보는 영업팀도 이해할 수 있도록, 그림마다 "그래서 사업적으로 무슨 뜻인가"를 글로 적는다.

- [ ] 그래프의 비즈니스적 의미를 텍스트로 기술한다(그래프와 함께 비즈니스적 해석을 반드시 포함).
- [ ] 군집별 마케팅/리스크 관리 전략 제언을 포함한다.
- [ ] 리포트를 아래 권장 섹션 구조를 참고해 작성한다(구조는 참고이며 내용이 핵심).

  - 실행 제언 (대상/메시지/액션)

## 결과 예시 (명세 참고)

명세는 "정답이 아니라 참고 예시"이며 레포지토리 구조는 달라도 된다고 했다. 예시는 군집 수 결정 결과, README의 페르소나 정의, SHAP 해석 문장을 보여 준다.

**군집 수 결정 예시**

- Elbow Method: K=4에서 기울기 변화 (Inertia 급감 후 완만)
- Silhouette Score: K=4일 때 0.42로 최대값 → 최적 K=4 선정
- PCA Explained Variance: PC1(45%) + PC2(28%) = 73% 설명력

**README 예시 (요약)**

- 페르소나 정의: 군집마다 이름(예: VIP, 주의군), 수치 특징(소득, 부채비율, 연체 횟수 등), 행동 해석, 추천 액션(→ 마케팅 또는 관리 방안)을 한 줄씩 적는다.
- SHAP 해석: Global은 가장 영향이 큰 변수를, Local은 특정 고객의 변수별 기여도(예: 연체 횟수 +0.35)와 거절 확률을 적는다.

자세한 문구는 명세 PDF의 결과 예시를 참고한다.

## 명세에서 확인할 점

- **거절 기준 숫자**: "연체(is_overdue=1) 예측 확률이5 이상인 고객"에서 숫자가 깨져 있다. 0.5로 보이지만 원문 PDF에서 확인이 필요하다.
- **보너스 대시보드의 출력**: 보너스 1은 "이탈 확률과 SHAP 설명"을 보여 주라고 하지만, 이 데이터의 분류 타겟은 연체 여부(`is_overdue`)다. "이탈 확률"을 연체 확률로 읽으면 되는지 확인이 필요하다.
- **분류 모델의 출처**: Global 해석의 입력이 "Mission 23에서 학습한 분류 모델"인데, 이 레포에서 같은 방식으로 다시 학습해도 되는지, 이전 미션의 모델을 가져와야 하는지 명세에 적혀 있지 않다.
- **분류 모델의 입력 변수**: 타겟 변수 제외는 "군집화 분석 시에는"이라고만 적혀 있다. `is_overdue`는 `credit_score`로 만들어지는 값이라, 분류 모델 입력에 `credit_score`를 넣을지 뺄지에 따라 SHAP 결과가 크게 달라진다. 명세에는 이에 대한 지시가 없다.
- **Dependence Plot 변수 개수**: 결과물에는 "특정 변수 1개 이상"이라고 했지만, 변수 선택 기준은 "Summary Plot 상위 변수 1~2개 + 비즈니스 의미가 큰 변수 1개"(즉 2~3개)다.
- **버전 명시 파일**: "shap/scikit-learn 버전을txt에 명시한다"에서 파일 이름이 잘려 있다. `requirements.txt`로 보인다.
